# V3.0 商品采集脚手架规范

> 给后续接入各平台 Scraper 的人看的; 当前 (V3.0) 仅搭骨架, 真实数据留 V3.x.

## 1. 现状

当前 `backend/app/services/scraper_registry.py` 有:

- `Scraper` 抽象基类: `name` / `search(ingredient)` / `fetch_price(sku_id)`
- `ScraperRegistry` 全局注册表
- `StubScraper` 占位实现 + 2 个已注册 (xiaoxiang, meituan_waimai)

所有真实 scraper 都继承 `Scraper` + 在文件底部调一次 `ScraperRegistry.register(YourScraper(...))`.

启动时由 dispatcher (在 scraper_jobs.py) 调 `ScraperRegistry.all()` 拿到已注册的全部实例, 串行/并发调度.

## 3. 调度入口

`run_daily_scrape()` 是 daily job 的入口:

```
09:00 ── run_daily_scrape()
            ├─ for scraper in ScraperRegistry.all():
            │     - search 每个高频食材 (原料表 + 之前的热搜)
            │     - upsert 到 product 表
            │     - 写一行 product_price 历史
            └─ return summary {platforms, products, prices, errors}
```

## 4. 关闭开关

`config.app.scraper.enabled = false` (默认): 调度器不会调用.
上线前改成 true + 在 config 注入各平台的额外配置.

## 5. 反爬约束

- 每个 scraper 自己维护 `httpx.AsyncClient` + rotating UA
- 不要全局共享一个 client: 不同平台反爬策略不一样
- 每个 search/sku 之间 sleep 1-3s, 实际接入时按平台 QPS 调整
- 单 SKU fetch_price 失败 5 次后进黑名单 1 小时, 不要无限重试

## 7. 验收指标

接入完一个平台后跑下面这三个 smoke:

```python
async def smoke(scraper: Scraper) -> bool:
    products = await scraper.search("番茄")
    assert len(products) > 0
    p = await scraper.fetch_price(products[0].sku_id)
    assert p and p.price > 0
    return True
```

接到 `make smoke-scrapers PLATFORM=xiaoxiang` 这种 CI 钩子里.
