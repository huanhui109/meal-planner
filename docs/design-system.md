# 设计系统

H5 与微信小程序共用同一套设计语言。**唯一真源是 `shared/tokens.ts`**，两端的样式文件都是
生成物，不允许手改：

```
shared/tokens.ts  ──node scripts/gen_tokens.mjs──┬─▶ frontend/src/styles/tokens.css
                  （--check 会校验是否漂移）      └─▶ miniapp/src/styles/_tokens.scss
```

`make ci` 里跑 `node scripts/gen_tokens.mjs --check`，只要有人绕开源文件改了生成物，
流水线立刻失败。要改颜色或圆角，改 `shared/tokens.ts` 然后 `make gen-tokens`。

### 令牌命名约定（踩过坑，务必遵守）

`shared/tokens.ts` 里的键名用 camelCase 写，生成器会自动转成 **kebab-case**：

| 源（`shared/tokens.ts`） | 生成物 | 手写引用时 |
|--------------------------|--------|------------|
| `layout.pageMax` | `--layout-page-max` | `var(--layout-page-max)` |
| `color.onInk` | `--color-on-ink` | `var(--color-on-ink)` |
| `font.trackingTight` | `--font-tracking-tight` | `var(--font-tracking-tight)` |
| `layout.tapTarget` | `--layout-tap-target` | `$layout-tap-target`（小程序） |

规则很简单：**每个大写字母前插一个 `-` 并整体小写**。
`ink2`、`ink3` 这类「小写字母 + 数字」的键不会被动，仍然是 `--color-ink2`。

⚠️ 曾经因为生成器漏做这步转换，`--layout-pagemax`、`--color-onink` 之类的变量名
和 CSS 里的引用对不上，浏览器**不会报错**，只是静默回退到初始值 —— 表现是
页面最大宽度失效、TabBar 高度归零、按压区变小。所以：

- 手写 CSS/SCSS 时一律用 kebab 形式；写错了没有任何提示。
- 改完令牌后跑一次 `make gen-tokens`，再跑 `make ci` 校验漂移。
- 排查「样式没生效」时，先在浏览器里 `getComputedStyle(document.documentElement).getPropertyValue('--your-token')`，
  返回值是空字符串就说明键名对不上。

## 1. 颜色

设计稿的取色逻辑：**中性灰承载 95% 的面积，彩色只用来表达语义**。
所以界面上看不到大面积蓝紫渐变，只有黑、白、灰，加一点绿和橙。

| 令牌 | 值 | 用途 |
|------|----|------|
| `color.bg` | `#e9e9ee` | 页面底色（比卡片暗一档，靠明度分层） |
| `color.screen` | `#f7f7f9` | 次级背景 / 内嵌区域 |
| `color.card` | `#ffffff` | 卡片 |
| `color.ink` | `#1c1c1e` | 主文字 / 主按钮底色 |
| `color.ink2` | `#8e8e93` | 次要文字、单位、说明 |
| `color.ink3` | `#c7c7cc` | 占位、未选中图标、禁用 |
| `color.line` | `#efeff2` | 分隔线（几乎不可见，只做暗示） |
| `color.fill` | `#f2f2f4` | 输入框 / 次级按钮底色 |
| `color.accent` | `#34c759` | **完成 / 充足 / 达标** |
| `color.warn` | `#ff9f0a` | **临期 / 超预算 / 待处理** |
| `color.danger` | `#ff3b30` | 错误、删除 |
| `color.glass` | `rgba(255,255,255,.82)` | 悬浮 TabBar 的毛玻璃 |

规则：

- 绿色只表示"完成/充足"，橙色只表示"需要注意"，**不用来装饰**。
- 主按钮永远是纯黑胶囊（`color.ink`），一屏最多一个，代表"现在最该做的事"。
- 卡片用阴影而不是描边分层；`color.line` 只在列表行之间用。

## 1.5 品牌标记 (Logo)

矢量唯一源是 `assets/logo/*.svg`，几何由 `scripts/gen_logo.mjs` 生成（不手改生成物）。

| 文件 | 用途 |
|---|---|
| `logo-mark.svg` | 仅图形。头像、favicon、TabBar 等小尺寸场景 |
| `logo-mark-inverse.svg` | 深色底反白版 |
| `logo-full.svg` | 图形 + 「饭决」+ 副标，登录页/侧栏横排用 |
| `logo-mono.svg` | 单色版，用于飞书卡片（飞书模板不支持彩色） |

几何：28px 圆角方底；碗口上方两片叶子（叶脉断线）；碗的侧剖轮廓（半圆 + 底弧）；
外圈沿弧线排 7 个圆点代表一周 7 天，"今天"那点用 `accent` 绿实心，其余 `ink-3`。

**使用规范**

- 安全区 = 图形高度的 25%，四周不得放进任何元素。
- 最小使用尺寸 24px（小于这个尺寸时 7 个圆点会糊在一起，改用单色变体）。
- 禁止：拉伸变形、换色、加投影、旋转、叠在复杂照片上。
- 名称永远是「饭决」，副标「今天吃啥，交给饭决」；文案唯一源在 `shared/brand.ts`，
  不要在页面里手写品牌名（`gen:logo --check` 与 `gen:tokens --check` 会在 CI 里拦住漂移）。

## 3. 字体与字号

字体栈：`-apple-system, "SF Pro Text", "PingFang SC", "Helvetica Neue", "Microsoft YaHei"`。

| 令牌 | 值 | 用途 |
|------|----|------|
| `font.title` | 29px | 页面大标题 |
| `font.number` | 26px | 卡片里的核心数字 |
| `font.heading` | 19px | 区块标题 |
| `font.body` | 15px | 正文 |
| `font.label` | 13px | 次要信息、按钮小号 |
| `font.caption` | 12px | 卡片标签、脚注 |
| `font.micro` | 11px | TabBar 文字、角标 |

字距：全局 `-0.01em`，标题 `-0.03em`。中文默认字距偏松，收紧后更像 Apple 的排版。

## 4. 数字亲近感规范

界面上的数字要"一眼能读懂量级"，所以：

| 规则 | 正例 | 反例 |
|------|------|------|
| 金额**永远 1 位小数**，整数不带小数点 | `¥18.5`、`¥310` | `¥18.50`、`¥18.499999` |
| 热量、分钟、比例**取整** | `520 kcal`、`35 分钟`、`30%` | `519.6 kcal` |
| 数量最多 2 位小数并去尾随 0 | `2`、`1.5`、`0.25` | `2.00`、`0.250` |
| 日期用中文月日，不补 0 | `8月18日` | `08-18`、`2026-08-18` |
| 区间用短横线连接 | `8月18日 – 8月24日` | `8/18-8/24` |
| 进度用 `done/total 单位` | `12/14 餐` | `85.7%` |
| 单位用小号灰字跟在数字后 | `500` `g` | `500g`（大字号里） |
| 所有数字 `tabular-nums` | 金额上下对齐 | 等宽不等，跳动 |

实现都在 `shared/format.ts`（`formatMoney` / `formatQuantity` / `formatKcal` / `formatProgress` …），
两端共用，所以不会出现"H5 显示 ¥18.5、小程序显示 ¥18.50"。

## 5. 下一步指引规范

用户打开 App 的第一诉求是"我该干嘛"。所以每个页面遵守：

1. **一句状态说明**（页面 subtitle）：说清"现在是什么状态"，不是泛泛的欢迎语。
   - ✅ `本周菜单已排到 9月13日, 10/14 餐已完成`
   - ❌ `欢迎回来！`
2. **最多一个黑色主按钮**：代表当前唯一推荐动作。有次要动作就用灰底/描边胶囊。
3. **空状态卡 = 一句解释 + 唯一 CTA**，解释"为什么是空的"和"点它会得到什么"。

决策逻辑集中在 `shared/next-step.ts` 的 `nextStep()`，优先级从高到低：

| 顺序 | 触发条件 | 文案 | 动作 |
|------|----------|------|------|
| 1 | 正在生成 | AI 正在生成菜单 | 无按钮（可离开页面） |
| 2 | 偏好没填 | 先花 1 分钟填偏好 | 去填偏好 |
| 3 | 没有菜单 | 生成这周的营养菜谱 | 原地生成 |
| 4 | 菜单是草稿 | 确认这周的菜单 | 去确认 |
| 5 | 有食材要买 | 有 N 样食材要买 | 看采购清单 |
| 6 | 今天还有没做的餐 | 今天还有饭要做 | 看今天菜单 |
| 7 | 都做完了 | 这周的饭都安排好了 | 周菜单 |

H5 与小程序调用同一个函数，所以两端给出的"下一步"永远一致。改动规则后
`frontend/tests/shared.next-step.test.ts` 会立刻告诉你哪些分支变了。

### 语义色用法（不要用来装饰）

| 色 | 含义 | 出现位置 |
|---|---|---|
| `accent` 绿 | 完成 / 充足 / 达标 | 已做、库存充足、营养达标、时间线 sent |
| `warn` 橙 | 注意 / 临期 / 超支 | 3 天内到期、预算超出、生成中进度点 |
| `danger` 红 | 错误 / 失败 | 请求失败、时间线 failed |
| `ink` 黑 | 主行动 | 一屏唯一的实心胶囊按钮 |

### 全局进度点

生成要 1-2 分钟且允许离开页面，所以进度必须**全局可见**：
`useGenerationStore` 驱动，在 TabBar 的「周菜单」项、侧栏项、右上角头像上
显示一个橙色呼吸圆点（`prefers-reduced-motion` 下关闭动画）。

## 7. 布局

### 首页 Bento Grid

2 列网格，卡片按重要性跨列混排；≥1024px 的 H5 展开 4 列。

今日页从上到下（**一屏只有一个黑胶囊主按钮**）：

```
┌───────────────────────────────┐
│ 问候 + 8月18日 周二 · 工作日     │
├───────────────────────────────┤
│ 今日预算条（黑字大数 + 进度条）  │
├───────────────────────────────┤
│ 下一步卡（黑底，仅未就绪时出现）  │
├───────────────────────────────┤
│ 补单决策卡（缺口 + 起送价 + CTA）│
├───────────────────────────────┤
│ 今晚菜单卡（临期/食材/做法/已做） │
├───────────────────────────────┤
│ 自做 vs 外卖（改价即记）         │
├───────────────┬───────────────┤
│ 本周预算(跨2列) │ 营养 / 临期    │
├───────────────┴───────────────┤
│ 本周进度(跨2列)                 │
├───────────────────────────────┤
│ 今日流程时间线（三态圆点）       │
└───────────────────────────────┘
```

菜单就绪后不再渲染"下一步卡"——那时真正的下一步已经是补单卡或今晚菜单卡，
再挂一张只会稀释主行动。

小程序端固定 2 列（手机宽度下 3 列会让数字挤在一起）。

### 触控与安全区

- 所有可点元素触摸目标 ≥ 44px。
- 底部 TabBar 是悬浮胶囊：`left/right: 14px`、`bottom: calc(14px + env(safe-area-inset-bottom))`，
  页面内容留出等高的 `padding-bottom`，避免最后一行被盖住。
- H5 用 `100dvh` 而不是 `100vh`，避免 iOS Safari 地址栏收起时跳高。
- 输入控件字号 16px，防止 iOS 聚焦时自动放大。
- 全局 `-webkit-tap-highlight-color: transparent`，按压反馈统一用 `scale(.965)` + `0.14s`。

## 8. 动效

- 时长：`fast 0.14s`（按压）、`base 0.24s`（出现/展开）。
- 曲线：`cubic-bezier(0.22, 0.9, 0.3, 1)`——先快后缓，接近 iOS 的手感。
- 按压：`scale(0.965)`。
- 页面切换（H5）：`opacity + translateY(10px) + scale(.99)`。

## 9. 小程序端注意

- 单位写 `px`，由 Taro 的 `pxtransform` 按 **375 设计宽度**转成 `rpx`（1px → 2rpx），
  所以 `shared/tokens.ts` 里的 px 值两端语义一致。
- 小程序 `<image>` 不支持 SVG，所以图标不引图片资源：TabBar 图标用 `View` 的圆角与边框画，
  既能跟着主题色变，包体积也是 0。
- 小程序不支持 `backdrop-filter`，TabBar 用 `rgba(255,255,255,.82)` 模拟毛玻璃观感。
